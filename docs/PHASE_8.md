## How to test

```bash
npm test && npm run build
npm run dev                       # music starts with the first click / key; Settings > Audio > Music
BASE_PATH=/Nitrovolt/ npm run build && BASE_PATH=/Nitrovolt/ npx vite preview --port 4173 --host 127.0.0.1 &
node scripts/deploy-test.mjs      # sub-path, PWA, offline and determinism smoke test
```

In a Chromium browser on the preview URL: the address bar offers *Install*; after one visit, DevTools > Network > Offline and reload: the game still runs. Main menu > *How to play* and *About*.

## Design decisions

- **Menu first, physics later.** The menu needs only three.js and the app; the 1.2 MB (gzip) physics binary arrives in the background while the player browses, so the time to the first screen is about a seventh of before. Nothing else had to change because every Simulation already awaited `initRapier()`.
- **Same WASM bytes, different packaging.** The compat package was kept (no async-WASM bundler plugin, same engine build used by the tests and the ghost pipeline); only its embedded base64 is lifted into a file. The deploy test proves determinism end to end.
- **Generated, not downloaded, music.** Keeps the no-external-assets rule and the bundle small; one style per season gives each theme its own mood, and the menu / race / pause mixes follow the game state.
- **Precache everything.** About 7 MB on first visit (mostly the physics binary and the 100 author ghosts) buys a game that works on a plane; hashed file names make updates safe, and the cache is replaced as a whole per version.
- **Static hosting only.** Share links carry tracks in the URL hash, so the deploy is just files; GitHub Pages (or any static host) is enough.

## Known issues / not yet done

- Gamepad, tilt steering and haptics remain untested on physical hardware; frame rate untested on real GPUs (all automated runs use software GL).
- iOS Safari ignores `screen.orientation.lock` and the wake-lock API on older versions; the rotate hint covers portrait.
- The first visit downloads ~7 MB for offline play (on metered connections the browser still only fetches it once).
- Music is synthesised in real time and costs a little CPU on low-end phones; Music volume 0 stops the scheduler.
- No online leaderboards or cloud saves (by design: static hosting, data stays in the browser).
